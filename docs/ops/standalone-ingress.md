# Standalone ingress and readiness

The local-only overlay publishes Nginx at 127.0.0.1:4330 by default. The base Compose has no published ports; production TLS/domain configuration is deliberately not supplied by the local overlay. Never expose the cleartext local overlay publicly. App, PostgreSQL, Redis and RustFS have no host port mappings. Nginx joins edge only; the app joins edge and the internal data network. Database/cache/storage are on data only. This design assumes the containers and Docker host are trusted infrastructure; the private network is not a substitute for database/S3 authorization.

Nginx overwrites forwarded identity headers instead of accepting caller-supplied values. The application's configured trusted identity header is X-Cocina-Client-Id, set from the immediate peer address. Do not add another proxy or CDN without re-evaluating that trust boundary and rate limits. Docker Desktop can represent local clients with one peer address. The public VPS requires domain/TLS and ingress trust validation; no claim of production TLS acceptance.

General request bodies are limited to 2 MiB; the global PDF upload endpoint permits 50 MiB total multipart body (including embeddings). These are provisional acceptance limits, not a guarantee every 50 MiB upload will work; validate real product upload size, Next.js limits and memory usage in F5.6/F6. The application framing policy DENY is preserved, and application CSP remains intact. Access logs omit query strings and authorization/cookie fields; Docker json-file logs rotate at 10m x 3 for every runtime service. Error logs are not claimed to be free of sensitive request data; review before production.

Health in S3 mode uses a read-only ListObjectsV2 limited to the authorized global-pdfs/ prefix, MaxKeys=1, using application credentials and a bounded abort signal. Database, Redis and S3 checks run in parallel. S3 unavailable gives 503 without provider detail in the public response; local storage mode retains the prior health response. No object write or delete is performed by readiness. Nginx checks the application health endpoint; all five runtime containers have health checks. This does not prove private document access or full PDF upload acceptance.

The proxy acceptance probe (`CC_STANDALONE_DISPOSABLE_TEST=true python3 scripts/tests/test-standalone-proxy.py`) targets only the fixed disposable project cocinacore-f55-test and loopback 4330. It checks pages/CSS, unauthorized APIs, body limits using headers only, health, private network topology, published port and configured log rotation. The isolated storage outage/recovery is a separate controlled test; never stop an original or production service. F5.4 open checks remain independent gates.
