### L3 — Recipe and plan contracts
- `listPersistentRecipes(scope, options)` returns current saved-recipe versions, defaults to active recipes, and scopes by both authenticated `tenantId` and `userId`; it is a read-only query inside the repository transaction.
- Saved recipe ingredients preserve optional quantity/unit strings; saved recipe versions do not provide a prep-time field, so a pure engine must represent preparation time as unknown rather than invent it.
- Existing structured-plan parsing exposes slot, ingredients, and optional historical prep minutes; its candidate format is reusable without adding schema or persistence behavior.
- `UserMealPlanRow` contains `period`, `calendar_payload`, and timestamps but no plan start date. The engine may exclude a planned duplicate only when its input carries an explicit matching date and slot; the Today adapter must not infer a calendar date from plan creation time.
